# Документация LeadFlow CRM/ERP

Эта папка — актуальный технический аудит проекта по состоянию кода на **2026-08-29** (коммит `a74ab2e`). Она заменяет собой более ранние документы в корне репозитория (`README.md`, `PROJECT_OVERVIEW.md`, `PROJECT_REPORT.md`, `SETUP_GUIDE.md`), которые датированы 2026-06-13/06-24 и с тех пор устарели минимум на 40+ коммитов (добавлены RBAC, сброс пароля, календарь, переводы между складами, статусы каталога, пагинация в нескольких разделах, сканер штрихкодов). Старые файлы в корне пока не удалены и содержат полезную историю решений по дням, но как источник текущего состояния им доверять нельзя.

## Что это за проект

LeadFlow — full-stack CRM/ERP для розничной и оптовой торговли (целевой рынок — Центральная Азия). Backend: FastAPI + async SQLAlchemy 2.0 + PostgreSQL. Frontend: React 19 + Redux Toolkit (RTK Query) + Tailwind CSS. Система покрывает цикл: клиенты → каталог → заказы → склад → поставки → финансы → зарплата с KPI.

## Методология

Всё, что написано ниже, проверено непосредственно по коду (грепы по роутерам/моделям/зависимостям, чтение репозиториев, реальные запросы к работающему backend на `localhost:8000`, `npm audit` / `pip-audit`). Там, где утверждение — предположение, а не факт из кода, это явно помечено фразой «предположение, требует проверки».

**Целевой хостинг подтверждён командой (не выводится из кода однозначно): Render.com.** В репозитории при этом остаются мёртвые/устаревшие следы Fly.io и Railway — это технический долг на чистку, а не открытый вопрос (подробности в [known-issues.md](./known-issues.md#8-мёртвая-конфигурация-flyio-и-railway-целевой-хостинг--rendercom) и [setup.md](./setup.md#деплой)). Важно: на Render.com развёртывание «как есть» сейчас сломает `secure`-флаг JWT-куки и ссылки сброса пароля — см. критичный пункт №4 в [gaps-and-roadmap.md](./gaps-and-roadmap.md).

## Итоговая оценка (коротко)

Система функционально насыщена и не является прототипом: 30+ доменных сущностей, ~155 API-эндпоинтов, 27 RTK Query слайсов на фронте, реальная бизнес-логика (списание/возврат склада при заказах, аудит истории заказов, генерация зарплаты по KPI, ABC/XYZ-анализ, P&L-отчёт, импорт/экспорт каталога, сканер штрихкодов). Для внутреннего использования командой из нескольких десятков сотрудников — функционала достаточно уже сейчас **при условии устранения двух критичных находок ниже**. Для передачи внешним клиентам или роста до сотен пользователей есть значимые пробелы: RBAC подключён только к 6 из 37 заведённых прав доступа (остальное — грубая проверка «админ/не админ»), часть складских write-операций доступна любому авторизованному пользователю без проверки роли, автотестами покрыты не более трети доменов, во фронтенд-зависимостях подтверждено `npm audit` 3 high-severity уязвимости, в бэкенд-зависимостях `pip-audit` нашёл 84 известных advisory в 20 пакетах (в основном транзитивные/dev, но есть и в `cryptography`/`starlette`/`python-multipart`, задействованных в каждом запросе).

⚠️ **Критично перед реальной эксплуатацией**: удаление клиента и удаление филиала в текущем коде каскадно и безвозвратно стирают связанные данные (заказы клиента; склад, остатки и историю поставок филиала) без единого предупреждения — оба сценария подтверждены построчным чтением кода, не предположение. Подробности — [known-issues.md, пункты 1–2](./known-issues.md#критично-целостность-данных).

Подробности и приоритизация — в [gaps-and-roadmap.md](./gaps-and-roadmap.md) и [known-issues.md](./known-issues.md).
